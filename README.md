# Список желаний v2.0.0

Личный журнал желаний и покупок для Railway + PostgreSQL.

## Что изменилось в v1.6.0

- Расширение **«В желания»** теперь единое для Chrome и Safari и работает с тем же бесплатным DOM-экстрактором цены.
- Добавлен безопасный импорт из iOS «Команд»: `/add?source=ios-shortcut&share_url=...`.
- Добавлен Android Web Share Target: после установки PWA пункт «Список желаний» появляется в системном меню «Поделиться».
- Мобильная ссылка сохраняется до входа, удаляется из адресной строки до проверки и запускает существующий `/api/product-preview` только один раз.
- Источник Safari/Chrome с готовой ценой по-прежнему не вызывает Railway и OpenAI; подтверждённая арифметика не перезаписывается AI.
- Инструкции находятся в `mobile/ios-shortcut`, `mobile/android` и `browser-extension/SAFARI.md`.

## Расширения браузера

- Chrome на Mac: загрузи папку `browser-extension` через `chrome://extensions`.
- Safari на Mac для временной проверки: Safari → Настройки → Разработчик → Add Temporary Extension и выбери папку `browser-extension`.
- Safari на iPhone/iPad и постоянная установка на Mac: упакуй эту же папку через Apple Safari Web Extension Packager; готовые команды есть в `browser-extension/SAFARI.md`.

Расширение запрашивает только `activeTab`, `scripting` и `storage`. Оно читает только активную страницу после ручного нажатия.

## Что изменилось в v1.5.0

- Добавлено Chrome-расширение **«В желания» для Mac** в папке `browser-extension`.
- Расширение читает уже отрисованную активную вкладку после ручного нажатия, поэтому не зависит от HTML, который Touch показывает Railway, и не вызывает OpenAI API.
- Для Touch используются точные DOM-источники `a.price.changePrice`, `.old_new_price`, `.economy`, `#new_price`, `#old_price`, `data-nowprice` и `data-price`.
- Незнакомые магазины обрабатываются универсальным DOM/JSON-LD резервом: название, текущая и старая цена, скидка, вариант и главное изображение.
- Данные передаются в приложение через URL-фрагмент `#import`; браузер не отправляет содержимое фрагмента Touch или Railway.
- Импорт сохраняется на время входа, затем автоматически открывается заполненная карточка. Результат повторно проверяется арифметикой в приложении.
- Проверено на сохранённой реальной карточке Touch SKU `118636`: расширение извлекает `21 599 − 7 050 = 14 549 ₴`, источник `browser-extension:touch-dom`, статус `VERIFIED`.

## Установка расширения на Mac

1. Открой `chrome://extensions` и включи «Режим разработчика».
2. Нажми «Загрузить распакованное расширение».
3. Выбери папку `browser-extension` из корня проекта.
4. На странице настройки вставь HTTPS-адрес своего приложения «Список желаний» и сохрани.
5. Закрепи значок «В желания», открой карточку товара, дождись цены и нажми значок.

Расширение запрашивает только `activeTab`, `scripting` и `storage`: оно не читает историю и не имеет постоянного доступа ко всем страницам.

## Что изменилось в v1.4.1

- Исправлен «липкий» конфликт: подтверждённая свежая цена теперь снимает предупреждение от более раннего устаревшего ответа, но две равносильные текущие цены по-прежнему блокируются.
- Для Touch добавлен безопасный свежий запрос с пятиминутным ключом CDN и проверкой обеих языковых карточек без `clear_cache`.
- Цена сверяется по независимым данным точного SKU во встроенных системах страницы (товарная аналитика, eSputnik, checkout); дубли не увеличивают доверие, известный устаревший `agec_detail` не участвует.
- Конфликт запускает бесплатные резервные маршруты до AI. Подтверждённая арифметика `21 599 − 7 050 = 14 549 ₴` завершает проверку без токенов.
- Добавлен регрессионный тест реального сбоя Railway: устаревший первый ответ + свежая карточка должны дать `14 549 ₴`, а не пустое поле.

## Что изменилось в v1.4.0

- Исправление проверено на фактически открытой карточке Touch SKU `118636`, а не на придуманной разметке. На момент снимка страница показывала `21 599 − 7 050 = 14 549 ₴`.
- Полная страница подтверждает цену бесплатной арифметикой (`VERIFIED`). Урезанный ответ Railway без ценового блока подтверждается двумя Product/Offer источниками той же карточки (`STRUCTURED`). В обоих случаях AI не вызывается.
- Структурированные данные оцениваются по валюте, наличию, сроку действия и совпадению прямого URL товара. Старая цена в `del`, `old_price` или зачёркнутом блоке накладывает veto.
- DOM-цены читаются из ближайшего блока главного товара. Цены рекомендаций, баннеров, рассрочки и других карточек больше не смешиваются с главным SKU.
- Одиночное неподписанное число теперь не считается надёжной ценой ни на одном магазине. Автоподстановка разрешена только после арифметического, структурированного или точного web-подтверждения.
- При настоящем конфликте `gpt-5-mini` использует Web Search с ограничением домена и обязан подтвердить прямую карточку/тот же SKU. Каталог, поиск, рекомендация, старая цена и сумма скидки отклоняются.
- `gpt-5.6-terra` получает ту же точную web-проверку только если основной ответ конфликтный или непригодный. Попытки, кэш и факт расхода теперь отражаются честно.
- Сохранились кэш одинаковых решений, максимум `2` изображения и жёсткий суточный предел `8` AI-вызовов. При конфликте только цены изображения не отправляются, reasoning принудительно `low`.

## Уровни доверия к цене

1. `VERIFIED` — старая цена минус скидка точно равна текущей.
2. `SALE_PAIR` — текущая и старая цена найдены в товарном блоке, скидка вычислена.
3. `STRUCTURED` — точный Product/Offer или текущий DOM-селектор подтверждает SKU.
4. `WEB_VERIFIED` — AI открыл точную карточку, источник совпал с товаром и уверенность не ниже `0.85`.
5. Любое одиночное, старое или конфликтующее значение блокируется; поле цены остаётся пустым для ручной проверки.

## Что изменилось в v1.3.1

- Исправлен Touch: серверные Product/Offer-данны больше не могут оставить в карточке старую зачёркнутую цену.
- Для Touch добавлена обязательная перепроверка отрисованной карточки, даже если первый ответ уже содержит название, картинку и одну цену.
- Добавлен тест реальной акционной связки Touch `21 599 − 6 350 = 15 249`.

## Что было добавлено в v1.3.0

- Добавлен **бесплатный детерминированный контроль цены** до обращения к AI.
- Распознаётся типичная акционная связка: старая зачёркнутая цена → размер скидки → фактическая текущая цена.
- Сервер проверяет арифметику без токенов OpenAI, например `21 599 − 7 100 = 14 499`.
- Если арифметика подтверждена, текущая цена получает статус `VERIFIED` и **блокируется от перезаписи AI**.
- Зачёркнутая цена и сумма скидки хранятся отдельно и отображаются в карточке товара.
- Основной AI-инспектор переключён на дешёвый `gpt-5-mini`.
- `gpt-5.6-terra` используется как fallback только при конфликте/неоднозначной цене.
- Кандидаты цен получают роли `current`, `old`, `discount`; AI запрещено выбирать `old` или `discount` как фактическую цену.
- Structured Outputs остаются включены: модель выбирает только из уже найденных кандидатов.
- При ручном изменении цены отметка автоматической проверки очищается, чтобы старая верификация не выглядела действующей.

## Railway

Основные переменные:

```env
DATABASE_URL=...
SESSION_SECRET=...
ADMIN_NAME=Иван
ADMIN_USERNAME=...
ADMIN_EMAIL=...
ADMIN_PASSWORD=...
```

Для AI-инспектора добавь в **Railway → Variables**:

```env
OPENAI_API_KEY=sk-...
AI_INSPECTOR_ENABLED=true
AI_INSPECTOR_MODEL=gpt-5-mini
AI_INSPECTOR_FALLBACK_MODEL=gpt-5.6-terra
AI_INSPECTOR_MAX_IMAGES=2
AI_INSPECTOR_DAILY_LIMIT=8
AI_INSPECTOR_CACHE_MINUTES=60
```

`OPENAI_API_KEY` хранится только на сервере и не отправляется в браузер. Не добавляй реальный ключ в GitHub.

Если `OPENAI_API_KEY` отсутствует или API временно недоступен, «Список желаний» продолжает работать на обычном парсере.
